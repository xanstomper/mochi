dashboard-auth.js holds the two decisions the daemon's dashboard route makes per request, and both currently leak. (1) dashboardResponseToken(reqToken, tokenOk, realToken) decides which token the served dashboard HTML may embed; today a request that arrives with NO token (or a wrong one) is silently handed the REAL daemon bearer token, so any local process — or any website the user visits — can fetch the dashboard and walk away with full API credentials. (2) corsAllowOrigin(origin) returns the wildcard '*' for every origin, letting any site read authenticated API responses cross-origin. Fix dashboard-auth.js: the real token may be embedded only when the request itself proved possession of it (tokenOk), otherwise the embeddable token is ''; CORS may reflect an Origin only when it is an http(s) origin on a loopback host (localhost, 127.0.0.1, [::1] — any port), and must grant nothing (no '*', no reflection) for any other origin or a missing/malformed one. Export isLocalhostOrigin(origin) and corsHeadersForOrigin(origin) helpers implementing the origin rule, and keep corsAllowOrigin(origin) returning the reflected origin or null.
