search.js exports searchFiles(root, query), the fallback text search used when no ripgrep binary is present. It only ever matches literally: every regex metacharacter in the query is escaped, so there is no way to search by pattern (all identifiers matching get\w+, calls shaped like foo(...), and so on). Add an opt-in regex mode: searchFiles(root, query, { regex: true }) compiles the query as a real regular expression (still case-insensitive). Regex mode needs a guard: validate the pattern before compiling — reject patterns over 512 characters and patterns that do not compile — and on rejection RETURN (never throw) an error string beginning 'Invalid regex:' (for the length case the message must state the maximum is 512), because the tool layer surfaces returned strings to the model as recoverable errors. Literal mode behavior must not change at all. Also export validateRegex(pattern) returning the error string or null.
