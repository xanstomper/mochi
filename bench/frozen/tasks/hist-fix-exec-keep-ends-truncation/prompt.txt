collect.js exports OutputCollector, the per-stream output accumulator for spawned commands: construct with a byte cap, push(chunk) per output chunk, then read result() and wasTruncated. Its truncation destroys exactly the part that matters: once output exceeds the cap it keeps only the HEAD and discards the rest of the stream, so for a long build or test run the failure summary at the END is lost and the command has to be re-run just to see why it failed. Rework the accumulator so an overflowing stream keeps the head AND a rolling tail (roughly half the cap each), eliding the middle with a marker that preserves the literal '[truncated]' anchor other tools grep for; the stream must keep consuming after overflow so the tail keeps arriving, total retained text must stay bounded (cap plus the marker), and under-cap output must pass through byte-identical with wasTruncated false.
