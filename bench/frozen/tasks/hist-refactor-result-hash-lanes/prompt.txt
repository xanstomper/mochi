result-hash.js exports hashToolResult(text) → hex key string, used to detect repeated identical tool results. Its BigInt 64-bit FNV-1a is too slow for the hot path: every tool result in an output-heavy run pays multi-millisecond BigInt hashing. Replace it with the two-lane 32-bit construction: lane 1 is 32-bit FNV-1a over the string's code units (offset basis 0x811c9dc5, prime 0x01000193, via Math.imul); lane 2 is FNV-1a over each code unit rotated ((ch << 9) | (ch >>> 7)) & 0xffff with offset basis 0x1b873593 and multiplier 0x85ebca6b; the key is lane1's hex followed by lane2's hex zero-padded to 8 chars. The two decorrelated lanes are what keep distinctness strong (including order sensitivity: different orderings of the same characters must hash differently) without BigInt. Contract: deterministic for identical inputs, distinct keys for distinct realistic outputs, and hashing a ~48K-character result must take well under a millisecond-scale budget (median of repeated runs < 1.5 ms on ordinary CI hardware).
