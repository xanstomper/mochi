frontmatter.js contains mochi's two hand-rolled YAML frontmatter parsers: parseSkillFrontmatter (the skill loader) and parseManagerFrontmatter (the skill manager — importer, Claude interop, curator). The loader handles YAML block scalars (`description: >-`, `notes: |`, indicators like `|2`/`>+`): it consumes the indented continuation lines, folds `>` blocks (adjacent lines join with a space, blank lines become paragraph breaks), joins `|` blocks with newlines, applies chomping, and trims. The manager never learned any of this — it reads line by line, so a block-scalar description stays the literal string ">-" and the continuation lines are dropped or misread as their own keys.

Extract ONE shared block-scalar implementation and use it from both parsers:
1. Shared helpers: a block-scalar indicator test (a value consisting of `|` or `>` followed only by digits/`+`/`-`), the folded-block line folder, and a reader that, given the frontmatter lines and the indicator line's index, consumes exactly the following blank-or-indented continuation lines and returns the scalar text (chomping applied, trimmed) plus the index of the last consumed line.
2. The loader keeps its exact observable behavior, but its inline block handling is replaced by the shared reader.
3. The manager gains block-scalar handling via the same shared reader: when a value is a block-scalar indicator, the parsed value is the consumed block text, and parsing resumes after the continuation lines (a continuation line containing a colon must NOT leak in as its own key).
4. Nothing else changes: both parsers keep their signatures, return shapes, frontmatter-detection behavior, and handling of plain scalars, quotes, and inline lists. After the change, the two parsers must agree on every document in the scalar/block-scalar subset.
