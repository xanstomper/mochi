atomic-fs.js provides atomicWriteFileSync(filePath, content, opts), which promises to preserve an existing file's permission bits across a rewrite. That promise breaks under a restrictive process umask: run a process with umask 0007 that rewrites an existing 0755 file through atomicWriteFileSync and the file comes back 0750 — the executable bit silently vanishes even though the module "preserved" the mode. Fix atomic-fs.js so the preserved mode (and an explicit opts.mode) survives any umask, without weakening its other guarantees (atomic rename, symlink fallback, no leftover temp files). Confirm with a scratch script under umask 0007: rewriting a 0755 file keeps it 0755 with the new content.
