spec-gate.js exports createSpecGate(isReadOnly) → { consider(name, argsBuffer, alreadyExecuted), parseAttempts }. It decides, per streamed delta of a tool call's JSON arguments, whether the call may speculatively execute: consider returns the parsed args when the call should fire now, else null; isReadOnly(name, args?) answers whether a call is read-only (with no args argument it answers the name-only question — argument-dependent tools answer for their safe default). The current implementation wastes the hot path: it JSON.parses the entire accumulated buffer on EVERY delta — including for calls that could never execute (mutating tools, whose parsed args are computed then discarded) and for buffers that are obviously incomplete. Refactor the gating so that (1) a call whose NAME alone is not read-only never triggers a parse attempt, (2) a buffer that cannot yet be complete JSON (its trimmed text does not end with '}') never triggers a parse attempt, and (3) behavior is otherwise identical: already-executed calls never fire; a complete read-only call fires exactly when its full JSON has arrived; an argument-dependent tool (read-only only for some argument values) fires only when the complete args also pass the with-args check; malformed JSON never throws. parseAttempts must reflect the real number of JSON.parse attempts.
