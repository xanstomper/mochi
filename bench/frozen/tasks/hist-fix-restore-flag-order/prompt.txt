classify.js exports classifyCommand(cmd), a shell-command risk classifier returning 'low', 'network', or 'destructive'. Its git-restore handling is order-sensitive in a way that flips verdicts on identical operations: `git restore --source=HEAD --staged -- a.ts` — an index-only restore that leaves the worktree untouched and should be 'low' — is classified 'destructive' merely because another flag precedes --staged, while the same flags in a different order classify 'low'; the `-S` short form of --staged is misclassified too. Fix classify.js so flag order never changes the verdict: a restore segment containing --staged or -S anywhere (and no --worktree/-W anywhere in the segment) is 'low'; any --worktree/-W makes it 'destructive' regardless; a bare `git restore <path>` stays 'destructive'; and a --staged appearing only in a LATER shell segment (after ; & or |) must not excuse an earlier worktree restore. Do not change any other classification.
