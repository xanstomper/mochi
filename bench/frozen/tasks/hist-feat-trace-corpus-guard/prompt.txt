prune.js exports pruneTraces(workspaceDir, maxFiles, maxBytes), the janitor that keeps <workspace>/traces bounded (newest maxFiles runs, under maxBytes, oldest first out). It has a data-loss flaw: a run that COMPLETED (its trace contains a task:completed or task:failed entry) but whose trajectory export has not been built yet is pruned exactly like debris — and the raw trace is the only copy of that run's step-level record, so the distillation corpus silently loses finished runs. Add corpus protection to prune.js: a completed run's trace must never be pruned until its export exists at <workspace>/exports/trajectory-<runId>.jsonl. Incomplete/crashed runs (no terminal entry) get no protection, malformed trace lines are skipped (a file whose only terminal-looking line is malformed JSON counts as not completed), exports are detected by filename scan (no content reads, no index file), and only would-be victims may be content-checked. Export the helpers you build (exportedTrajectoryRunIds, traceFileHasTerminalEvent, isUnexportedCompletedTrace) alongside pruneTraces. pruneTraces must keep its signature, caps behavior for unprotected files, return count, and never-throw property.
