run-verify.js exports runVerificationCommand(cmd, cwd), which runs a candidate's verification command and resolves { passed, code } (passed iff exit 0; it must never reject). It currently mangles any realistic command: it splits the string on spaces and execs the pieces, so quoted arguments containing spaces ("a b"), env assignments (EXPECTED=1 node check.js), and && chains all break — verification fails candidates for the harness's own parsing, not for their code. Fix run-verify.js so the command string is executed verbatim through a real shell, keeping the exact resolve contract (resolve { passed, code } for every outcome, including a missing binary or a non-zero exit — never throw or reject).
