This measures the harness machinery (loop, journal, compaction, subagents, steer, discipline) — it says nothing about how a real frontier model behaves inside that machinery, and nothing about task-level intelligence.

- Token figures are wire estimates (chars/4) of fake-provider payloads, useful for relative comparison between runs, not billing truth.
- One fixture, one task shape. Mileage across many task shapes (debugging, refactors, greenfield) is future work for this factory.

## Addendum — ranked findings for the integrator (hand-written; the tables above are machine-generated)

**Batches.** Batch A (9/9 runs, scripted summarizer with NO session memory) is archived at `bench/endurance/results/mileage-prefix-router.md`: baseline 0/3, chaos 1/3, chaosb 0/3. Batch B (the tables above, 8/9 runs) differs only in the factory's scripted summarizer carrying read/display facts across summaries: baseline 3/3, chaos 0/3, chaosb 1/2 (chaosb-3 never got a fixture — host EPERM storm; chaosb-2's runner was killed by the same host hazard mid-resume, class X). The shipped bench code is exactly the batch-B code (plus a report-aggregation fix so future tables split chaos events per profile). No `src/` files were changed by this wave; every fix below is a harness recommendation, not a bench patch.

### F-1 — Exactly-once fails WITHIN a session (taxonomy F8) — highest frequency
A completed shell side effect whose evidence is rewound by an in-session digest/checkpoint is re-executed when the plan re-issues it. The run journal replays steps only at session start; the ExecutionRegistry dedup does not span context rewinds. Measured: batch B — 10 duplicate probe appends across 8/8 runs (every run duplicates at least the stage-1 probe); batch A — 8 duplicates across 7/9 runs, and one passing baseline accumulated 14. The guarded ledger append (the completion path a careful operator writes) never duplicated; the unguarded canary shows the raw exposure. Any real side effect without an idempotency guard — a deploy, a payment call, a file append — is silently repeatable after any compaction.

### F-2 — Discipline/finish machinery terminates healthy long runs (F7, with an F6 flavor) — highest severity
Two measured flavors. (a) Batch A baselines, 3/3 deterministic: after the background-catalog collect, a post-verify finish drive accepted `completed` at stage 3 of 5 — final summary is literally the collect step's note ("Collecting the background catalogue result."), verification vacuously green because the fixture's ORIGINAL test suite passes at the partial state. (b) All 6 chaos-a runs across both batches + 3 batch-A chaosb runs: "Stopped a deliberation loop; verification does not pass" — the run is killed while legitimately recovering (re-reads after compaction, flaky-backend retries, one recon re-spawn). Progress accounting via file-op deltas cannot tell a post-compaction re-read from deliberation, and the fixture's TDD-style suite is *supposed* to be red from stage 1 until stage 3 lands — nothing tells the discipline layer "red is expected mid-build", so a red suite arms the stopper. The subsystems fight: compaction creates the re-reads, discipline punishes them.

### F-3 — Heuristic checkpoint summaries are lossy in specific, costly ways (feeds F-2)
Across a checkpoint turn, `files-read` and display-tool outcomes deterministically vanish from the model's context (branch-tail fingerprints flip `+` → `−`); the checkpoint harvest carries changed files and verify outcomes but not read results or non-file tool results. Each drop costs re-walk turns and deliberation debt. The digest channel preserves more (it sees raw messages) but is expensive at small budgets: a passing baseline spends 23 of 68 model calls on aux summarization, and early smokes showed ~4KB digests that saved ~300 tokens. Batch B vs batch A isolates the value of summary fidelity: same harness, same task — baseline completion 0/3 → 3/3 from summarizer fidelity alone.

### F-4 — A provider-killed foreground subagent is very expensive before the parent learns anything
With the recon child's provider returning HTTP 500, the child burned ~140 model requests / ~170s of parent-blocked wall (provider failover + backoff inside the child) before the parent observed the failure; a 40s subagent timeout did not visibly bound it. Recovery itself works — the parent fell back to direct reads and stages 1–2 completed in 3/3 batch-B runs — but the storm costs ~40% of the run's wall clock and primes F-2's deliberation debt.

### F-5 — What already works: SIGKILL + journal resume and orphan reconciliation (positive result)
When a run survives to the catalog stage, the kill/resume path converges: batch-A chaos-1 passed the full gauntlet (196 parent turns, 40 compactions, journal replayed 22 steps on resume, steer deliverable landed, exactly-once ledger intact); batch-B chaosb-1 passed likewise (80 turns, 27 steps replayed). The orphaned background child after resume is observed and reconciled (collect → RUNNING → cancel-and-continue path exercised). This is the harness's strongest measured long-horizon behavior. Caveat: the resumed runner process itself died on a host write-EPERM in chaosb-2 (class X, environmental) — the journal/write path has no tolerance for write errors; worth a look even though the trigger was a host hazard.

### Recommended harness fixes (ranked; structural — deliberately NOT made here)
1. Idempotency across rewinds: check journal-step completion before re-executing a step whose post-state was rewound out of context (per-step idempotency keys), not only at session start. (Fixes F-1.)
2. Discipline accounting: exempt post-compaction re-reads and tool-error retries from deliberation; make the deliberation stop non-terminal on tasks whose verification is expected-red mid-build (inject a commit directive instead of stopping). (Fixes F-2b.)
3. Finish drive: require task-level completion evidence (the run's own stage/checkpoint contract), not merely a green repo suite, before accepting a finish on multi-stage work. (Fixes F-2a.)
4. Checkpoint harvest: carry read results and non-file tool outcomes, or route checkpoints through the digest channel's richer excerpt. (Fixes F-3.)
5. Subagent failure economics: cap a foreground child's provider-retry storm with a budget shared with the parent, and surface child failure to the parent fast. (Fixes F-4.)

### Factory-side fixes made while building this bench (all under `bench/`, each verified by the runs above)
- Runner runs the agent with `unattendedAllow: true` (headless subagent spawns are denied by default without it — first smoke died on exactly that veto).
- Scripted summarizer: state first, one fact per line (single-line list rendering made items bleed into each other and broke evidence matching); router session memory for read/display facts (batch-B delta).
- Fixture test file is existence-gated so the mutation gate has teeth on the new code from stage 1 (an early smoke's gate correctly rejected a claim because the suite didn't cover the feature).
- Driver: `--flag 0` parsing (0 was silently replaced by defaults), fixture writes ride out host EPERM bursts (retry + write-health gates + per-scenario and per-batch retries), report is rewritten incrementally after every run so a host kill cannot take finished records with it.
