Capabilities

Everything a harness needs.
Nothing it doesn't.

Sixteen specialized agent roles, thirty-plus native tools, adaptive context, and a daemon you can drive from anywhere — without a single runtime JS dependency.

Compiled Rust core

Tokenization, budget math, compaction planning, and loop decisions run natively via N-API — with parity-tested TypeScript fallbacks so nothing breaks on cold installs.

Goals, DAGs & teams

Persistent goals decompose into task DAGs executed by role-diverse agent swarms — lead, coder, reviewer, debugger, and 12 more.

Persistent daemon

mochi daemon start then drive it over HTTP — jobs, approvals, resume, and recurring cron-scheduled runs on port 8642.

Adaptive context engine

Token budgets, compaction planning, project memory, and retrieval across files, symbols, references, imports, and git history.

Budgets & permissions

Token, cost, time, tool, model, and agent limits. Safe / ask / auto permission system with git checkpoint and rollback underneath.

Deep run traces

mochi trace <goalId> replays any run end to end. Full-text session history in SQLite+FTS5 with deep redaction.

Polyglot codegraph

15-language registry with tree-sitter AST intelligence: find_callers, type_hierarchy, replace_symbol, and complexity analysis built in.

Any model, any provider

Model-agnostic OpenAI-compatible provider with capability routing (fast / coding / reasoning / review), budget-aware fallback, and multi-key credential pools.

Standalone binary

npm run build:bin ships a native binary that needs no runtime at all — or run it under Node 22 / Bun.

Architecture

Two engines, one harness.

Pure compute lives in a compiled Rust crate. Everything else — model I/O, TUI, tool execution — stays in a thin TypeScript frontend. Every native path has a tested fallback.

native/mochi_core RUST · ZERO-DEP

  • BPE tokenization — 0.28 ms per 100k chars, compiled heuristic tokenizer
  • Compaction cut planning — O(n) walk, zero GC pressure
  • Workspace indexing — N-API nativeSearchDir, 50k files in 3.8 ms
  • Agent-loop decisions & budget math, in-process memory sharing

Frontend & harness TYPESCRIPT

  • Model I/O — OpenAI-compatible provider, streaming, credential rotation
  • TUI — direct ANSI rendering, no webview, no Electron
  • Tool bus — 30+ tools: edit, patch, shell, search, git, subagent…
  • Persistence — SQLite+FTS5 sessions, run traces, project memory

Why the gap

  • Dual-engine architecture — hot paths in compiled Rust with N-API in-process memory sharing, not subprocess spawns.
  • No startup blockers — zero synchronous shell probes during initial frame generation.
  • No webview tax — direct terminal ANSI rendering; no Electron or heavy UI layers.
  • Intelligent caching — (mtime, size) keyed read cache eliminates redundant I/O across agent turns.
  • Headless-grade — full harness under 20 MB RAM for CI, containers, and embedded nodes.
  • Regression-gated — npm run bench:memory fails CI above ceilings, so the wins can't silently regress.

Why Mochi

Built different, on purpose.

01Autonomy as a primitive, not a bolt-on

Goals persist, decompose into task DAGs, and execute through role-scoped swarms with independent verifiers and an outcome judge — the harness itself ships the work.

02Fail-safe by construction

Every Rust-native path has a parity-tested TypeScript fallback. Whitespace-drift-tolerant patching refuses ambiguity rather than guessing. Budgets cap tokens, cost, time, and tools.

03It learns your repo

Project memory carries cross-session engineering facts; local harness learning records which recovery strategies actually worked and reuses them.

04Observable to the last token

Durable run traces with deep redaction, SQLite+FTS5 full-text session search, and per-turn checkpoint rollback via git.

Get started

Up and running in a minute.

Requires Node 22+ or Bun. Zero runtime dependencies.

Build & runbash
# clone and build
git clone https://github.com/xanstomper/mochi.git
cd mochi && npm install && npm run build

# one-shot agent run
mochi "add a rate limiter to the auth service"
Daemon, teams & tracesbash
# persistent daemon over HTTP
mochi daemon start --host 0.0.0.0
mochi daemon send "finish the auth flow"

# role-diverse agent team
mochi team "ship the payments refactor"

# replay any run end to end
mochi trace <goalId>
