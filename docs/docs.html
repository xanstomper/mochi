Documentation

Mochi — Minimal Orchestrative Coding Harness Intelligence — is an autonomous coding agent for the terminal. This page covers installation, core concepts, and the CLI. Deep dives live in the repo's docs/.

Installation

Requires Node 22+ or Bun. Mochi has zero runtime JavaScript dependencies.

# clone and build
git clone https://github.com/xanstomper/mochi.git
cd mochi
npm install && npm run build

# optional: standalone native binary (no runtime needed)
npm run build:bin

A memory regression gate (npm run bench:memory) runs in CI after every build and fails above 80 MB codegraph import / 95 MB runtime import — lazy-loading wins can't silently regress.

First run

# interactive TUI
mochi

# one-shot headless run
mochi "add a rate limiter to the auth service"

# multi-agent swarm
mochi team "ship the payments refactor"

One-shot runs execute to completion with verification; mochi trace <goalId> replays the whole run afterwards.

Architecture

Mochi is a dual-engine harness:

  • Rust core (native/mochi_core) — a zero-dependency compiled crate handling BPE tokenization (0.28 ms / 100k chars), compaction cut planning (0.12 ms on 250-turn transcripts), N-API workspace indexing (50k files in 3.8 ms), and agent-loop decisions. No GC pressure, in-process memory sharing.
  • TypeScript frontend — model I/O, tool execution, TUI rendering via direct ANSI (no webview, no Electron), and persistence (SQLite+FTS5).
  • Parity-tested fallbacks — every native path has a TypeScript equivalent, so CI and cold installs work when the Rust binary is absent.

Implemented systems include the event bus, model routing by capability profile, budget-aware fallback, codex-style multi-file patches with whitespace-tolerant matching, hook pipelines (before_*, after_*, on_*), speculative execution, credential pools, and multiple workspaces. See the architecture blueprint for the full deep dive.

Native tools

Thirty-plus built-in tools, grouped:

Editing

edit (anchor-matched, whitespace-tolerant), patch (multi-file *** Begin Patch format that refuses ambiguity rather than guessing), write, delete, replace_symbol (AST-driven whole-symbol rewrite), rename_symbol (project-wide atomic), search_replace_multi, regex_replace.

Code intelligence

get_function, find_callers, type_hierarchy, find_references, find_definitions, analyze_code (cyclomatic complexity, code smells). read also supports skeleton: true for 85% token reduction on AST outlines.

Execution & inspection

shell (background jobs supported), repl (stateful Node/Python/Shell), search (N-API accelerated, sub-millisecond), glob, inspect, plus git, memory, todo, skill, and subagent.

Permissions run through a safe / ask / auto system with git checkpoint and rollback underneath.

Daemon

mochi daemon start --host 0.0.0.0   # port 8642
mochi daemon send "run the test suite"
mochi daemon cron add "0 9 * * *" "triage open issues"

The daemon exposes start / status / jobs / send / approve / resume / cron / stop over HTTP, so editors, scripts, and CI can drive the same long-lived agent. Recurring jobs run on schedule; approvals gate anything the permission system marks as ask.

Sessions & traces

Every session is stored in SQLite with FTS5 full-text search (mochi session search "compaction bug"). Every goal run produces a durable trace with deep redaction — replay it with mochi trace <goalId> to see model turns, tool calls, verifications, and recoveries in order.
